# design-check-skill

Appleプラットフォーム（iPhone / iPhone Duo（折りたたみ）/ iPad / Mac / Apple Watch）向けのUI設計・画面仕様・デモモック・開発プロンプトを、ID付きのプラットフォーム別チェックリストで監査し、「抜け」（必要なのに無い・曖昧な項目）を見つけて直すためのAgent Skillです。

- チェックリストは 共通／iPhone／iPad／iPhone Duo／Mac／Apple Watch／アイコン・成果物形式 の7区分、各項目にID（例： `C-05`, `I-02`）
- 監査は1回で終わらせず、抜けを直して再チェックする「監査ループ」を回します
- パスごとに、まだ使っていない観点を1つ選んで見直します（チェックリスト順、ユーザーフロー順、状態マトリクス、支援技術の利用者、プラットフォーム横断の一貫性、極端なデータと文言の長さ、文言と用語、作る人の目の8種類）
- 終了条件は「新規の抜けゼロ」のパスが3回連続（上限8パス）

## できること／できないこと

できること：
- 既存の設計・仕様・モック・プロンプトに対する全項目の判定（OK／抜け／対象外）と、ID・根拠・修正案の提示
- テキスト成果物と、ソースを編集できる視覚成果物（SVG / HTML / Figma 等）の修正と再チェック
- 編集できない画像（PNGのみ等）に対する修正指示書の作成（修正版を受け取ったら続きから再開）
- パスごとの記録と最終報告

できないこと：
- デザインの新規制作（レイアウト、モック、アイコン、素材は作りません）
- デザインの「好み」の判定（好みは「提案」として分けて書きます）
- 対象外プラットフォームの強要（例： Mac版のないアプリにMacモックを求めません）

## 使い方

1. 監査対象（設計書、画面仕様、モック、プロンプトなど）と、そのアプリの対応プラットフォームを渡す
2. 依頼する。例：
   - 「このモックをチェックして」
   - 「プロンプトのデザイン抜けを見て」
   - 「iPad向けの抜けがないか監査して」
3. 生成物： 修正済みの成果物（または修正指示書）と、最終報告（パスごとの表、抜けの内訳、保留、提案、最終判定）

## 前提条件

- 監査対象の成果物と、アプリの対応プラットフォームが分かっていること（書かれていなければ記述から判断し、根拠を報告します）
- 数値基準は Apple の Human Interface Guidelines 等の公式情報（2026年10月時点で確認）に基づきます。OSのメジャーアップデート時は再確認してください

## 自分の環境に合わせる箇所

HIGより厳しい「自社ルール」として入れている項目です。自組織の方針に合わせて調整してください。

- `A-04` アイコンの全外観（デフォルト／ダーク／クリア／ティント）を自前で用意（HIG上は未用意分をシステムが自動生成）
- `A-06` アイコンへの文字入れを全面禁止（HIG上は「不可欠な場合だけ」）
- `A-07` 視覚成果物にPNGプレビューを必須で添付
- `C-19` モック・サンプルデータに実在の人名・住所・企業を使わない
- `A-01` のアイコン作成ツール（Icon Composer か kajisho5/fresnel 等）

## よくある質問

**Q. デザインを作ってくれるスキルですか？**
A. いいえ。監査専用です。抜けを見つけて直しますが、新しいデザインは作りません。編集できない画像は描き直さず、修正指示書を出します。

**Q. なぜ「3パス連続ゼロ」まで回すのですか？ 同じものを3回見ても意味がないのでは？**
A. そのため、パスごとに**毎回新しい観点**で見直します。1つのループで同じ観点は2回使いません（観点は8種類で、上限も8パス）。違う見方で3回続けて新規の抜けが出なければ「安定して抜けがない」と判断します。修正で生じた不整合も新規の抜けとして数えます。

**Q. 自分の判断が必要な抜けはどうなりますか？**
A. 機能範囲・課金・プラットフォーム追加などの設計判断に関わるものは、勝手に直さず選択肢と推奨案を出して「保留」にします。保留は最終報告に一覧で残ります。

**Q. チェックリストの数値（44×44ptなど）の根拠は？**
A. Apple の Human Interface Guidelines（Accessibility、App icons など）です。SKILL.md 末尾の「出典・参考」に公式ページへのリンクがあります。

**Q. hig-design-skill との関係は？**
A. hig-design-skill がHIGに沿ってデザイン（設計書とモック）を作る側、このスキルがそれを監査して抜けを直す側です。単独でも使えます。
